# 앤스로픽 엔지니어링 표준 — 편집 방침

지은이 제시리미트리스 · 기획·제작 Muze AI · 펴낸곳 소셜브레인
목적: 정식 출간물이자 Muze AI(AX 기업)의 포지셔닝 자산.

## 이 책이 살려면 반드시 들어가야 할 것

2026-09-02 기준 제1·2장까지 조판 완료. 아래는 **아직 원고에 없는** 것들이며,
이것이 없으면 이 책은 "빅테크가 하는 말을 한국어로 잘 정리한 책"에 머문다.

**1. 다트인사이트 실전 사례 — 최우선**
저자는 개발자가 아니라 정책학 전공 IT 기획자다. 이 이력은 약점이 아니라
**이 책 주장의 가장 강한 증거**다. "코드를 직접 치지 않는 기획자가 명세만으로
실제 운용되는 투자 시스템을 만들었다"는 것 자체가 방법론의 증명이다.
단, 선언이 아니라 증거여야 한다 — 실제 명세 문서와 산출물을 4부에서 보여줄 것.
GitHub spec-kit, AWS Kiro와 싸울 유일한 무기이기도 하다.

**2. 방법론의 실패 모드 절**
현재 원고는 명세 주도 개발에 단점이 없는 것처럼 읽힌다. 시니어 독자는 반드시
묻는다 — 명세 자체가 틀렸으면? 명세 쓰는 비용이 기능보다 큰 작은 변경은?
명세와 코드의 표류는 어떻게 감지하나? 탐색적 요구사항은?
오래 남는 방법론서는 자기 한계를 스스로 적는다.

**3. 선행 사례와의 차별점 명시**
'Spec-Driven Development'는 빈 땅이 아니다. GitHub `spec-kit`, AWS Kiro가
같은 용어로 이미 들어와 있다. 이들을 1부 어딘가에서 언급하고 무엇이 다른지
밝혀야 "표준을 선도한다"는 포지션이 선다. 언급 자체가 권위 신호가 된다.

**4. 장별 실전 체크리스트**
현재 두 장을 다 읽어도 독자가 손을 움직일 지점이 없다. 방법론서의 승부는
"월요일 아침에 뭘 하지?"에 답하느냐다. `.worksheet` 조판은 이미 준비돼 있다.

**5. 부제의 검색어**
현재 부제 "명세 주도 AI 네이티브 개발"은 아무도 검색하지 않는 조어다.
서점 검색은 키워드로 일어난다 — "클로드 코드", "Claude Code", "AI 코딩".
제목의 격은 유지하고 부제만 검색어를 담게 바꾸는 것을 검토할 것.

## 미확정 사항

- **다트인사이트 소개 문구** — `manuscript/03-지은이.md`에 자리만 있고 비어 있다
- **대상 독자** — 1~2장은 시니어 엔지니어 수준인데 5부는 1인 빌더를 겨냥한다.
  하나로 정하는 편이 둘 다 노리는 것보다 낫다
- **주소·ISBN** — 판권지에 "서울특별시 마포구"까지만 있다
- **제목 리스크** — 『앤스로픽 엔지니어링 표준』은 공식 간행물로 오인될 소지가 있다.
  표지·판권지에 무관계 고지를 넣었으나 출판사 법률 검토를 권한다

## 원고 편집 규칙

- **측정되지 않은 수치를 쓰지 않는다.** "0%", "100% 일치", "95% 확보", "10배"는
  이미 걷어냈다. 규모를 보여주는 예시(30분, 1,200줄, 15분)는 남긴다
- **원어 병기는 첫 등장 1회.** LLM은 프롤로그에서만 병기, 이후 약어만
- **"앤스로픽식"이라는 수식**은 근거가 있을 때만. 앤스로픽 내부 프로세스는
  공개 확인되는 사안이 아니다
- 절 제목을 고치면 `manuscript/04-차례.md`도 같이 고친다

## 구조

```
표지 → 약표제지 → 표제지 → 지은이 → 차례 → 프롤로그
     → 제1부 도비라 → 제1장 → 제2장 → … → 판권
```

원고는 5부 11장 + 프롤로그 + 에필로그. 한 장에 3개 절이 기본.
차례(`04-차례.md`)가 전체 구조의 정본이다.
