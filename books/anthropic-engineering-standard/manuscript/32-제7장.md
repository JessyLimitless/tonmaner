# [07]{.ch-num} 실행 도구로서의 MCP (Model Context Protocol) 표준


<!-- 여기부터 본문 -->


## MCP의 본질과 위상: '데이터 구조(두뇌)'를 현실에 연결하는 '표준 팔다리(Tool Adapter)'

거대언어모델(LLM)이 아무리 방대한 지식을 학습하고 4대 명세 체계를 통해 정밀한 추론 능력을 갖추었더라도, 본질적으로 모델은 '텍스트를 생성하는 고립된 상자(Isolated Sandbox)'에 불과합니다.

모델 혼자서는 로컬 파일 시스템에 저장된 마크다운 문서를 읽어 들일 수 없고, 데이터베이스에 정규화된 레코드를 영속화할 수 없으며, 인터넷망에서 최신 기술 아티클을 스크랩해 올 수도 없습니다. 엔지니어가 직접 터미널에서 명령을 대신 쳐주거나 복사·붙여넣기를 반복하지 않는 한, 모델의 정교한 설계는 현실 세계에 단 1바이트의 영향도 미치지 못합니다.

이 문제를 해결하기 위해 앤스로픽이 제정한 공개 개방형 표준이 바로 Model Context Protocol(MCP)입니다.

### USB-C의 혁명: 도구 연동의 M × N 복잡도를 M + N으로 압축하다

과거 AI 애플리케이션 개발에서 외부 시스템 연동은 극심한 파편화의 늪에 빠져 있었습니다.

- OpenAI 진영의 독자적 Function Calling 규격
- LangChain 진영의 프레임워크 종속적 Tool 인터페이스
- 각 데이터베이스(PostgreSQL, SQLite), 서비스(GitHub, Slack), 파일 시스템마다 제각기 작성해야 하는 커스텀 글루 코드(Glue Code)

만약 5개의 서로 다른 AI 에이전트 도구가 10개의 외부 데이터 소스와 통신해야 한다면, 엔지니어는 5 × 10 = 50개의 어댑터를 각각 구현해야 했습니다. 새로운 LLM이 등장하거나 데이터베이스 인터페이스가 바뀔 때마다 모든 연동 코드가 깨지는 악몽이 반복되었습니다.

<!--figure: mcp-mesh | 곱셈이 덧셈으로 바뀌는 지점. 표준이 하는 일은 늘 이것 하나다.-->

앤스로픽은 하드웨어 업계가 USB-C 포트 하나로 모니터, 충전기, 외장 하드, 키보드를 통합했듯이, AI 생태계의 모든 데이터 소스와 실행 환경을 단 하나의 표준 프로토콜로 통합했습니다.

이제 에이전트는 특정 벤더의 전용 플러그인 규격을 배울 필요가 없습니다. 시스템은 표준화된 JSON-RPC 2.0 통신 규약을 통해 "어떤 리소스가 존재하는지(Resources)", "어떤 프롬프트 템플릿이 제공되는지(Prompts)", "어떤 함수를 호출할 수 있는지(Tools)"를 런타임에 동적으로 발견(Discovery)하고 안전하게 조작합니다.

### 두뇌(Data Schema)와 팔다리(MCP)의 물리적 결합

여기서 가장 중요한 엔지니어링 통찰이 도출됩니다. [MCP는 결코 독자적으로 존재하지 않는다]{.dot}는 사실입니다.

많은 초심자가 MCP를 단순히 '화려한 외부 도구 모음'으로 오해합니다. GitHub MCP, Slack MCP, Brave Search MCP 등을 마구잡이로 에이전트에 붙여놓고는, 에이전트가 어떤 도구를 언제 써야 할지 몰라 헤매는 상황을 마주합니다. 팔다리만 무수히 많이 달아놓았을 뿐, 그 팔다리를 제어할 중추신경계가 없기 때문입니다.

MCP의 본질은 앞서 우리가 구축한 4대 명세, 특히 `03_DATA_SCHEMA.md`에 선언된 데이터 구조를 현실 세계에 입출력하는 '물리적 드라이버(Driver)'입니다.

::: {.formula}
[두뇌와 팔다리]{.label}

- **두뇌 — `03_DATA_SCHEMA.md`** — "문서는 반드시 UUID 형태의 `id`, 중복 없는 `slug`, UTF-8 텍스트인 `raw_content`, 그리고 `tags` 배열을 가져야 한다."
- **팔다리 — Filesystem &amp; Database MCP Server** — 두뇌의 스키마 제약에 따라 실제 로컬 디렉토리에 마크다운 파일을 생성하고(`tools/write_file`), PostgreSQL 테이블에 SQL 파라미터를 바인딩하여 안전하게 `INSERT`를 실행한다(`tools/query`).
:::

두뇌(명세)가 방향과 형식을 지시하고, 팔다리(MCP)가 현실의 디스크와 네트워크를 건드립니다. 이 연결 고리가 확립될 때 비로소 에이전트는 단순한 '채팅 봇'을 넘어 프로덕션 환경을 자율적으로 조작하는 [실행형 에이전트(Actionable Agent)]{.dot}로 도약합니다.

### MCP의 3대 핵심 프리미티브(Primitives)

앤스로픽의 MCP 명세 표준은 모델이 현실과 상호작용하는 통로를 세 가지 프리미티브로 엄격히 구분합니다.

::: {.table-wrap}
| 프리미티브 | 역할 | 동작 방식 | 지식 아카이브 SaaS 적용 예시 |
|---|---|---|---|
| **Resources** (자원) | 데이터 읽기 (Read-only) | URI 기반으로 파일, DB 레코드, API 데이터의 내용을 컨텍스트로 불러옴 (REST GET과 유사) | `memo://vault/tech/docker.md` URI를 통해 로컬 마크다운 문서 내용을 직접 로드 |
| **Tools** (도구) | 상태 변경 및 연산 (Action) | 모델이 시스템에 부수 효과(Side-effect)를 일으키는 함수 실행 (POST/PUT/DELETE와 유사) | `scrape_url({ url })` 도구로 웹 아티클 추출, `save_document({ payload })` 실행 |
| **Prompts** (프롬프트) | 재사용 가능한 워크플로우 템플릿 | 사용자와 에이전트가 특정 작업을 표준화된 방식으로 시작할 수 있는 사전 정의된 컨텍스트 세트 | `archive_article` 템플릿을 호출하여 수집부터 태깅까지의 표준 워크플로우 즉각 구동 |
:::

이 세 가지 프리미티브는 완벽히 모듈화되어 있으므로, 개발자는 비즈니스 로직을 변경하지 않고도 로컬 파일 시스템 리소스를 언제든 클라우드 S3 리소스로 갈아 끼울 수 있습니다.

### 안전성과 권한 통제: 무제한 실행의 공포를 통제하는 샌드박스

에이전트에게 쉘(Bash) 실행 권한이나 DB 삭제 권한을 무제한으로 열어주는 것은 프로덕션 환경에서 자살행위와 같습니다.

MCP는 태생적으로 '최소 권한의 원칙(Principle of Least Privilege)'을 준수하도록 설계되었습니다.

- **명시적 도구 노출** — 서버는 자신이 허용하는 도구의 목록과 파라미터 JSON Schema만을 클라이언트에게 공개합니다.
- **인간 승인 루프(Human-in-the-loop Gate)** — 클라이언트 환경(Claude Code, Desktop 등) 설정에 따라 파일 삭제, 원격 코드 실행, 대량 DB 업데이트와 같은 위험 동작(Destructive actions)은 실행 전 반드시 엔지니어의 명시적 승인을 거치도록 통제할 수 있습니다.

### 요약: 명세의 완성을 위한 물리적 도약

명세서가 아무리 훌륭해도 그것을 코드로 옮기고 인프라에 배포할 손발이 없다면 이상에 불과합니다. 반대로 손발(MCP)이 아무리 빨라도 따라야 할 설계도(명세)가 없다면 시스템을 파괴하는 흉기가 됩니다.

::: {.callout}
`03_DATA_SCHEMA.md`라는 가장 엄밀한 헌법적 두뇌 위에, MCP라는 표준화된 팔다리를 장착하십시오.
:::

다음 절에서는 우리 프로젝트인 마크다운 지식 아카이브 시스템 구축에 필수적인 3대 표준 도구, 즉 Filesystem MCP, PostgreSQL MCP, 그리고 Puppeteer/Fetch Scraper MCP를 로컬 환경에 직접 구성하고 바인딩하는 실무 구현으로 들어가겠습니다.


## 마크다운 아카이브 시스템 구축에 필요한 3대 표준 도구 실무 구성

지식 아카이브 SaaS 시스템의 두뇌인 4대 명세(PRD, ARCHITECTURE, DATA_SCHEMA, UI_SPEC)가 수립되었다면, 이제 에이전트가 현실의 파일과 데이터베이스, 외부 웹 네트워크를 직접 조작할 수 있는 '3대 핵심 실행 도구 파이프라인'을 구축해야 합니다.

실전 프로젝트인 지식 아카이브의 생명주기를 지탱하는 표준 MCP 도구는 다음과 같이 3개 레이어로 구성됩니다.

::: {.formula}
[3대 실행 도구 레이어]{.label}

1. **Filesystem MCP Server** — 로컬 디렉토리의 마크다운 파일 원시 입출력 및 실시간 감시 ([Phase 1] 뼈대).
2. **PostgreSQL MCP Server** — 정규화된 문서 엔티티, 전문 검색(Full-Text) 인덱스, 태그 매핑 조작 ([Phase 2] 영속성).
3. **Web Scraper (Puppeteer/Fetch) MCP Server** — 외부 기술 아티클 URL로부터 광고와 잡음을 제거한 순수 마크다운 추출 (수집 엔진).
:::

### 전체 아키텍처 토폴로지 및 JSON-RPC 연결망

에이전트 클라이언트(Claude Code 또는 CLI Runner)는 표준 입출력(stdio) 기반의 JSON-RPC 2.0 프로토콜을 통해 세 개의 MCP 서버 프로세스를 자식 프로세스(Subprocess)로 스폰하여 제어합니다.

<!--figure: mcp-stdio | 클라이언트는 서버를 자식 프로세스로 띄우고 표준 입출력으로만 말한다. 경계가 프로세스 단위로 그어진다.-->

### 3대 도구 통합 설정: mcp-servers.json

프로젝트 루트 또는 환경 설정 디렉토리에 MCP 서버들의 구동 명령과 격리 경로를 선언합니다. 이 파일 자체가 시스템 인프라 연동의 단일 진실 공급원 역할을 수행합니다.

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/absolute/path/to/project/vault"
      ]
    },
    "postgres": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-postgres",
        "postgresql://archive_admin:secure_pass@localhost:5432/knowledge_vault"
      ]
    },
    "web-scraper": {
      "command": "node",
      "args": [
        "./scripts/mcp-servers/puppeteer-scraper/dist/index.js"
      ],
      "env": {
        "PUPPETEER_HEADLESS": "true",
        "TIMEOUT_MS": "15000"
      }
    }
  }
}
```

### 도구별 실무 구성 및 계약 명세 연동

**(1) Filesystem MCP — 로컬 파일 시스템 격리와 원자적 I/O**

- **역할** — 로컬 볼트(Vault) 디렉토리 내의 `.md` 파일 탐색, 읽기, 쓰기.
- **보안 가드레일** — `server-filesystem`의 인자로 대상 디렉토리(`/project/vault`)를 명시적으로 고정함으로써, 에이전트가 상위 디렉토리(`../../etc/passwd` 등)로 이탈하는 경로 순회(Path Traversal) 공격을 원천 차단합니다.
- **노출 도구** — `read_file`(마크다운 파일의 UTF-8 원문 획득), `write_file`(신규 문서 생성 및 수정 사항 디스크 반영), `list_directory`(폴더 트리 구조 파악).

**(2) PostgreSQL MCP — 타입 무결성 쿼리와 인덱스 활용**

- **역할** — `03_DATA_SCHEMA.md` [Phase 2]에 정의된 DDL을 기반으로 SQL 쿼리 실행.
- **보안 가드레일** — 직접적인 `DROP TABLE`이나 DDL 변조를 방지하기 위해 일반 작업 세션에서는 DML(SELECT, INSERT, UPDATE) 권한만 부여된 전용 데이터베이스 롤(Role)을 연결합니다.
- **노출 도구** — `query`(파라미터화된 SQL 실행, 전문 검색 `@@ to_tsquery` 쿼리 수행 및 결과 반환).

**(3) Web Scraper MCP — DOM 정제 및 마크다운 변환 파이프라인**

외부 웹 문서는 구조가 제각각이고 불필요한 스크립트, 광고 배너, CSS가 가득합니다. 따라서 일반적인 단순 `fetch` 대신, 헤드리스 브라우저로 렌더링된 최종 DOM에서 본문 콘텐츠만 추출하는 전용 MCP 서버를 구성합니다.

다음은 `@mozilla/readability`와 `turndown`을 결합한 경량 Puppeteer Scraper MCP의 핵심 핸들러 구현체입니다.

```typescript
// scripts/mcp-servers/puppeteer-scraper/src/index.ts
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { CallToolRequestSchema, ListToolsRequestSchema } from "@modelcontextprotocol/sdk/types.js";
import puppeteer from "puppeteer";
import { JSDOM } from "jsdom";
import { Readability } from "@mozilla/readability";
import TurndownService from "turndown";

const server = new Server(
  { name: "web-scraper-mcp", version: "1.0.0" },
  { capabilities: { tools: {} } }
);

const turndown = new TurndownService({ headingStyle: "atx", codeBlockStyle: "fenced" });

// 도구 스키마 노출
server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [
    {
      name: "scrape_to_markdown",
      description: "웹페이지 URL을 방문하여 광고와 잡음을 제거하고 순수 마크다운으로 변환한다.",
      inputSchema: {
        type: "object",
        properties: {
          url: { type: "string", description: "스크랩할 대상 HTTP/HTTPS URL" }
        },
        required: ["url"]
      }
    }
  ]
}));

// 도구 실행 핸들러
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name !== "scrape_to_markdown") {
    throw new Error("Unknown tool");
  }

  const { url } = request.params.arguments as { url: string };
  const browser = await puppeteer.launch({ headless: true });

  try {
    const page = await browser.newPage();
    await page.goto(url, { waitUntil: "networkidle2", timeout: 15000 });
    const html = await page.content();

    // Readability 엔진으로 본문 추출
    const dom = new JSDOM(html, { url });
    const reader = new Readability(dom.window.document);
    const article = reader.parse();

    if (!article) {
      throw new Error("본문 콘텐츠를 추출할 수 없습니다.");
    }

    // HTML -> Markdown 변환
    const markdown = turndown.turndown(article.content);

    return {
      content: [
        {
          type: "text",
          text: JSON.stringify({
            title: article.title,
            byline: article.byline,
            markdown_content: markdown
          }, null, 2)
        }
      ]
    };
  } finally {
    await browser.close();
  }
});

const transport = new StdioServerTransport();
await server.connect(transport);
```

### 3대 도구가 연동된 자율 워크플로우 시나리오

세 도구가 완벽히 설정되면, 에이전트는 다음과 같은 복합 파이프라인을 인간의 개입 없이 단 한 번의 지시로 완결합니다.

:::::: {.worksheet}
#### 명령 — "기술 아티클 링크를 읽고 아카이브에 영속화하라"

1. **Web Scraper MCP** — `scrape_to_markdown({ url })` 호출 → 광고 제거된 제목과 순수 본문 획득.
2. **에이전트 두뇌 (명세 참조)** — `03_DATA_SCHEMA.md` 스펙에 맞춰 Frontmatter, Slug, Tags JSON 추출.
3. **Filesystem MCP** — `write_file({ path: "vault/tech/article-slug.md", content: "..." })` 실행.
4. **PostgreSQL MCP** — 파라미터 바인딩된 `INSERT INTO documents (title, slug, raw_content, source_url) VALUES ($1, $2, $3, $4)` 실행.
::::::

### 요약: 완벽한 실행 환경의 완성

도구가 파편화되어 있으면 에이전트는 무력해집니다. 반면, 표준화된 MCP 규격으로 구축된 3대 실행 도구는 에이전트에게 강력하고 안전한 물리적 작업대를 제공합니다.

- 로컬 디스크는 Filesystem MCP로 안전하게 통제되고,
- 영속적 데이터와 전문 색인은 PostgreSQL MCP로 무결성을 유지하며,
- 외부 지식의 유입은 Web Scraper MCP가 정제된 형태로 공급합니다.

::: {.callout}
이로써 에이전트는 완전한 실행 능력을 갖추었습니다. 다음 장부터는 이렇게 준비된 4대 명세와 MCP 도구 위에서 실제로 마크다운 지식 아카이브 시스템을 Phase 1부터 Phase 3까지 한 땀 한 땀 구현해 나가는 실전 개발의 여정으로 진입하겠습니다.
