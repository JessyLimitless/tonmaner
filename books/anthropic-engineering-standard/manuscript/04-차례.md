# 차례 {.contents .unlisted}

::: {.toc-item}
[프롤로그]{.toc-num} [왜 앤스로픽의 시니어 엔지니어들은 코드를 먼저 치지 않는가?]{.toc-title}

- 프롬프트 난사의 종말: 명세와 데이터 구조가 곧 시스템의 헌법이다
- 1인 개발자부터 빅테크 엔지니어링 팀까지 관통하는 새로운 표준
:::

::: {.toc-part}
[제1부]{.toc-part-n} 앤스로픽의 핵심 철학 — Spec-Driven 패러다임
:::

::: {.toc-item}
[01]{.toc-num} [헌법적 명세(Constitutional Spec)와 단일 진실 공급원(SSOT)]{.toc-title}

- '프롬프트 만능주의'의 붕괴: 컨텍스트 오염(Context Drift)과 스파게티 코드의 필연성
- 헌법적 AI 원리의 엔지니어링 적용: 시스템 제약과 규칙의 텍스트 선언
- 단일 진실 공급원(SSOT): 코드가 아닌 마크다운 명세가 시스템 원본이 되는 체계
:::

::: {.toc-item}
[02]{.toc-num} [비동기 RFC(Request for Comments)와 협업 정렬]{.toc-title}

- 구두 회의·슬랙 대화의 왜곡 vs 마크다운 명세 리뷰의 정합성
- 코드 리뷰 이전의 '명세 승인(Spec Approval)' 프로세스
- 프론트와 백엔드의 인터페이스 통신 에러를 구조적으로 없애는 계약 명세(Contract Spec)
:::

::: {.toc-item}
[03]{.toc-num} [점진적 단계별 빌드(Phase-Driven Iteration)]{.toc-title}

- 완벽주의의 함정: 왜 한 번에 거대한 시스템을 프롬프트로 생성하면 무너지는가?
- 4대 명세 문서 내부를 수평 분할하는 [Phase 1], [Phase 2], [Phase 3] 태그 전략
- 에이전트의 컨텍스트 윈도우 통제: 작업 단위 격리와 토큰 최적화 기법
:::

::: {.toc-part}
[제2부]{.toc-part-n} 4대 명세 프레임워크와 데이터 구조론
:::

::: {.toc-item}
[04]{.toc-num} [기획 명세와 시스템 아키텍처 (PRD.md & ARCHITECTURE.md)]{.toc-title}

- 01_PRD.md: 문제 정의, 핵심 가치 제안(UVP), 단계별 스코프 통제 템플릿
- 02_ARCHITECTURE.md: 풀스택 데이터 흐름과 상태 머신(State Machine) 설계
- 엔터프라이즈 환경 대응: 공공·금융 폐쇄망, 온프레미스 sLLM 및 망연계 설계 포인트
:::

::: {.toc-item}
[05]{.toc-num} [데이터 구조론과 UI 명세 (DATA_SCHEMA.md & UI_SPEC.md)]{.toc-title}

- 03_DATA_SCHEMA.md: 시스템의 뼈대 — 타입 무결성 DDL, 관계형 모델, API/Webhook 스키마
- 왜 데이터 스키마가 에이전트의 가장 강력한 환각 방지 가드레일인가
- 04_UI_SPEC.md: 컴포넌트 계층 구조, 디자인 토큰, 사용자 인터랙션 규칙
- 4대 명세 간 교차 검증(Cross-Referencing)을 통한 정합성 검증
:::

::: {.toc-part}
[제3부]{.toc-part-n} 앤스로픽 5대 워크플로우와 MCP 표준 실행 도구
:::

::: {.toc-item}
[06]{.toc-num} [앤스로픽 공식 5대 에이전트 아키텍처 실무]{.toc-title}

- 패턴 1 & 2: 프롬프트 체이닝(Prompt Chaining)과 지능형 라우팅(Routing)
- 패턴 3 & 4: 명세 섹셔닝 병렬화(Parallelization)와 오케스트레이터-워커(Orchestrator-Workers)
- 패턴 5: 평가기-최적화기(Evaluator-Optimizer) 루프를 통한 자동 단위 테스트 및 자가 교정
:::

::: {.toc-item}
[07]{.toc-num} [실행 도구로서의 MCP (Model Context Protocol) 표준]{.toc-title}

- MCP의 본질과 위상: '데이터 구조(두뇌)'를 현실에 연결하는 '표준 팔다리(Tool Adapter)'
- 마크다운 아카이브 시스템 구축에 필요한 3대 표준 도구 실무 구성
:::

::: {.toc-part}
[제4부]{.toc-part-n} 실전 프로젝트 — 마크다운 지식 아카이브 시스템 점진적 구현
:::

::: {.toc-item}
[08]{.toc-num} [\[Phase 1\] 로컬 마크다운 엔진과 핵심 뷰어 구축]{.toc-title}

- 01_PRD 기반 프로젝트 뼈대 생성과 무의존성 마크다운 AST 파서 엔진 구현
- 로컬 파일 시스템 감시자(File Watcher)와 04_UI_SPEC 기반 2-Pane 뷰어 컴포넌트 구현
- Phase 1 완성: 컴파일러 기반 빌드 검증 및 깃 커밋 고정
:::

::: {.toc-item}
[09]{.toc-num} [\[Phase 2\] 풀스택 데이터베이스와 지능형 웹 수집 엔진 구축]{.toc-title}

- 03_DATA_SCHEMA 기반 PostgreSQL 마이그레이션과 전문 검색(Full-Text Search) 인덱스 구축
- Puppeteer MCP 기반 웹 아티클 지능형 수집 및 마크다운 정제 파이프라인 연동
- Phase 2 완성: 전문 검색 UI 연동 및 백엔드 REST API 통합 검증
:::

::: {.toc-item}
[10]{.toc-num} [\[Phase 3\] 프로덕션 패키징 및 B2B 개방]{.toc-title}

- Docker 멀티스테이지 빌드 패키징과 환경 변수(Env) 격리 배포 아키텍처
- Public Share 읽기 전용 뷰어 서빙과 정적 슬러그 캐싱 엔진
- Phase 3 완성: B2B 확장을 위한 API Key 인증 체계 및 Webhook 이벤트 포털 구축
