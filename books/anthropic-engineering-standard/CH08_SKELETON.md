# 제8장 [Phase 1] 골격 — 공시 원문 수집과 정규화 코어

근거는 전부 `Dartai/dart-insight/` 실제 구현. 지어낸 것 없음.
독자가 만드는 것: 무료 DART OpenAPI 키 하나로 노트북에서 완결되는 공시 아카이브 코어.

## 이 장이 뒤집는 것

기존 제8장은 **성공하는 파서**를 만들었다. 실제 구현은 정반대 순서다.
`dart_client.py` 1,939줄에서 먼저 오는 것은 파싱이 아니라 **실패의 분류**다.
이 순서 뒤집기가 제8장의 논지다 — 명세는 성공 경로가 아니라 실패 경로부터 쓴다.

## 8.2 실패를 먼저 명세한다 — DART API 클라이언트

**이 장의 핵심 절.** 실제 `_call_api()`가 에러 코드를 세 부류로 가른다.

| 코드 | 성격 | 처리 |
|---|---|---|
| `010` `011` `100` `901` | 입력 오류 | **즉시 실패.** 재시도는 낭비 |
| `013` | 데이터 없음 | **정상 응답.** 에러가 아니다 |
| `020` 요청 제한 · `800` 시스템 점검 | 일시 장애 | 지수 백오프 재시도 |

가르칠 것 세 가지.

1. **`013`을 에러로 처리하면 정상 종목이 장애로 둔갑한다.** "데이터 없음"과 "가져오기 실패"는
   전혀 다른 사건인데, 자연어 명세는 이 둘을 구분하지 않고 넘어간다.
2. **재시도해도 되는 실패와 안 되는 실패를 명세가 갈라줘야 한다.** 입력 오류를 재시도하면
   호출 예산만 태운다.
3. **호출 예산을 코드가 강제한다** — `api_counter.can_call()`이 일일 한도를 넘으면 호출 자체를
   거부한다. 실제 코드 주석에 남은 경고: 보고서 코드 폴백은 CFS/OFS × 4보고서로
   **호출 예산을 8배로 튀긴다.**

→ 도해 `dart-error-taxonomy` (에러 3분류와 각 경로)

## 8.3 명세가 데이터를 이기지 못하는 자리 — 재무 정규화

**함정 A — 연결과 별도가 한 응답에 섞여 온다**
`fnlttSinglAcnt.json`은 `fs_div`로 CFS(연결)와 OFS(별도)를 함께 준다.
필터를 안 걸면 두 재무가 뒤엉킨다. 실제 구현은 CFS 우선, 없으면 OFS 폴백.

**함정 B — 분기 금액이 회사마다 단독이거나 누계다** (실측 근거 있음)

| 유형 | Q1~Q3 `thstrm_amount` | `thstrm_add_amount` |
|---|---|---|
| A형 (삼성전자·한화오션·동양 등 9사 중 8사) | 3개월 **단독** | 연초부터 **누계** |
| B형 (NH프라임리츠) | **누계** | 누계 (thstrm과 동일) |

`thstrm_amount`를 단독으로 가정하면 B형에서 누계를 분기값으로 오독한다.
`thstrm_add_amount`만이 두 유형에서 일관되게 누계다.

**규약** — 누계를 정본으로 세운 뒤 차분한다.

```
누계(Q1..Q3) = thstrm_add_amount  (없으면 thstrm_amount 폴백)
누계(Q4)     = thstrm_amount      (사업보고서 = 연간 누계, add 필드 없음)
단독(Q1) = 누계(Q1)
단독(Qn) = 누계(Qn) - 누계(Q(n-1))
```

**함정 C — 재무상태표는 차분하지 않는다**
BS는 시점 잔액(저량)이지 기간 발생액(유량)이 아니다. 차분하면 완전히 틀린 값이 나온다.

→ 이 장의 결론: **스키마에 타입만 적으면 부족하다. 유량인지 저량인지, 단독인지 누계인지
   — 의미 단위를 적어야 에이전트가 차분해도 되는지 안 되는지 안다.**
   이것이 "데이터 스키마가 가장 강력한 환각 방지 가드레일"의 실물 증거다(5.2절과 연결).

→ 도해 `quarterly-cumulative` (A형/B형 · 누계→단독 차분 · BS 제외)
